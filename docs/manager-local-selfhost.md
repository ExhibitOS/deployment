# Local selfhost adapter using Manager

This additive component reuses the public `exhibitos-manager` Install/Start/Stop/Restart/Retry jobs, operation lock, installation identity, ownership admission and writer/recovery fences. It does not create another lifecycle journal. `deployment-binding.json` is an immutable private configuration binding, not a progress record or executable permission.

`planSelfhost` reads an already prepared private Manager root, private OED document and explicitly pinned Manager executable. Its caller must supply the separately approved exact OED/manifest/Compose/executable SHA256 values. An image existing in cache, these hashes alone, or an old receipt do not establish signed release authenticity. The consumer must approve the release through its existing trusted process. The prerequisite binary must implement `install-existing-images --preserve-volumes --existing-images-only` from the linked Manager change; installing a binary or copying a bundle is outside this component.

The supported local profile has one digest-pinned Platform image, port 13200, one replica, the bundle's digest-pinned PostgreSQL service `database:5432` with database/user `exhibitos`, filesystem assets `data/assets`, and one environment password reference. Other valid OED targets/storage/ports remain unsupported, rather than being silently reinterpreted. The existing package generator provides the two-service fixed Compose shape and its private runtime.env; Manager independently validates the exact Compose against the approved manifest. The wrapper does not accept commands, generate secrets, download/load/build images, or interpret secret references as credential permission. Archive declarations remain bound to the approved manifest and Manager rechecks actual archive size/hash at Install.

Each mutation consumes a fresh opaque in-memory plan, explicitly acknowledges existing images and preserving volumes, rechecks private root/files/current binding and Manager engine state, repeats project census and effective Docker context verification, and launches the pinned Manager CLI with a frozen environment and explicit local DOCKER_HOST. Context/TLS selectors are removed. Remote TCP/SSH engines refuse. The Unix daemon/local proxy is trusted; point observations are not a hostile same-user exclusive snapshot. Manager's operation lock remains the mutation authority. Plan engine observations share a 20-second deadline. A mutation shares a 180-second deadline and bounds its Manager child to at most 120 seconds; timeout is uncertain, preserving the binding/jobs/root/volumes, with no automatic restart or rollback. The first binding uses exclusive creation and fsync; a failed/uncertain action preserves it and all candidate/data files. Re-open requires a freshly observed genuine plan. A first Install must observe an empty project; later failed Install uses retry-existing-images with exact prior UUID/attempt and its persisted cached-only policy, admitted inside the Manager operation lock before any history/backend mutation. The wrapper pins private jobs.json and links the exact response to its durable latest record. A failed normal Install is refused before child invocation; target drift at the lock is refused by Manager.

`stop` means stopping a failed candidate while preserving volumes. It is not schema/data rollback. There is no down --volumes, prune, cleanup or automatic retry. Manager jobs provide progress and safe error codes; wrapper receipts include no paths, endpoints, credential values, runtime.env hashes, raw process errors or process output.

A caller that independently prepares and approves private inputs can use the public Node API without exposing secret values:

```js
import {planSelfhost,applySelfhost} from './src/manager-selfhost.mjs';
const input={root:'/absolute/private/installation',oedPath:'/absolute/private/oed.json',
  managerPath:'/absolute/verified/exhibitos-manager',
  approved:{oedSha256,manifestSha256,composeSha256,managerSha256}};
const plan=await planSelfhost(input);
const job=await applySelfhost(plan,{action:'install',preserveVolumes:true,existingImagesOnly:true});
// Obtain a new plan before each explicitly requested start/stop/restart.
```

The four digest variables are supplied by the caller's trusted approval process; computing a hash of arbitrary current files or reading an old binding does not provide that approval. `runtime.env` must already exist privately with the supported typed values. The wrapper neither creates nor prints credentials. A failed job remains a failed job; normal Install retry is never silently converted to cached-only permission.
